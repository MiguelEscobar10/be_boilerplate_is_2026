### Prevención de entregas indebidas

En todos estos casos la reserva no cambia de estado, no se crea ninguna entrega y no queda ningún archivo nuevo.

| Id | Caso | Esperado | Resultado |
|---|---|---|---|
| E05 | Antes del inicio | 422 `ENTREGA_NO_HABILITADA` con `disponibleDesde` igual al inicio de la reserva | ✅ |
| E06 | Reserva PENDIENTE, RECHAZADA, CANCELADA o COMPLETADA | 409 con un mensaje que dice el estado (4 subcasos) | ✅ |
| E07 | Segunda entrega de la misma reserva | 409 "ya se registró". Se conservan la primera nota y su foto, y no se guardan archivos nuevos | ✅ |
| E08 | Cinco envíos simultáneos de la misma entrega | Uno responde 201 y cuatro 409. Hay una sola entrega y solo quedan las 2 fotos de la ganadora (ninguna huérfana) | ✅ |
| E09 | Otro arrendador (reserva ajena) | 403 "Solo el arrendador…" | ✅ |
| E10 | El arrendatario de la reserva intenta registrarla | 403 | ✅ |
| E11 | Sin sesión | 401 | ✅ |
| E12 | Reserva inexistente o id que no es UUID | 404 y 400 | ✅ |

## Frontend: pantalla de entrega

Probado con Chrome headless (Playwright) contra la rama de FE-08.1 y el backend de BE-08.1.

Datos de prueba: un arrendador, un arrendatario y dos reservas CONFIRMADAS. Una ya empezó y la otra empieza mañana.

Pantallas probadas: escritorio (1280×800) y móvil (375×812).

| Id | Caso | Resultado |
|---|---|---|
| F01 | Antes del inicio (móvil): al confirmar, el formulario dice "estará disponible desde el…" (422) y la reserva sigue CONFIRMADA | ✅ |
| F02 | Desde el inicio: aparecen el contador (40/500), la confirmación previa, el aviso "Entrega registrada. La reserva pasó a EN_CURSO." y la foto subida visible. En la base quedan 1 entrega y 1 foto | ✅ |
| F03 | Con la entrega ya registrada, el arrendador (móvil) y el arrendatario ven el detalle sin formulario | ✅ |

**Resultado: 5 de 5.** No hubo errores de JavaScript en la consola.

En el frontend, las pruebas de componentes cubren:
- no hay doble envío mientras se registra;
- el 409 refresca el estado;
- las validaciones locales: 6 fotos, PDF y más de 5 MB.

## Cómo repetirlo

```bash
DATABASE_URL="postgresql://postgres:postgres@localhost:5432/si_be_boilerplate_test?schema=public" npx prisma migrate deploy
npx vitest run --config ./vitest.config.e2e.ts test/qa/qa-08.1-entrega.e2e-spec.ts --reporter=verbose
```

Para el frontend:
1. Levanta el backend de esta rama.
2. Crea una reserva CONFIRMADA ya empezada y otra futura.
3. Levanta el frontend de FE-08.1 con `API_URL=http://localhost:3000/api/v1`.
4. Entra como arrendador a `/reservas/<id>/entrega`.
