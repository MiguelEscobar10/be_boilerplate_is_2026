## Defectos encontrados

Ninguno en H14.

Queda un pendiente de integración que no es un defecto. H14, criterio 1, dice que nadie puede **solicitar** fechas bloqueadas. Solicitar una reserva es BE-03.1, que todavía no está en `main`, así que hoy solo se pudo comprobar que el bloqueo impide **aprobar** (B03) y que el calendario muestra las fechas ocupadas (B05, F06). Hay que repetirlo cuando entre BE-03.1.

## Cómo repetirlo

```bash
DATABASE_URL="postgresql://postgres:postgres@localhost:5432/si_be_boilerplate_test?schema=public" npx prisma migrate deploy
npx vitest run --config ./vitest.config.e2e.ts test/qa/qa-14.1-bloqueos.e2e-spec.ts --reporter=verbose
```

Para el frontend:
1. Levanta el backend con una reserva CONFIRMADA en una publicación del arrendador.
2. Levanta el frontend con `API_URL=http://localhost:3000/api/v1`.
3. Entra como el arrendador al detalle de la publicación y pulsa "Bloquear fechas".
